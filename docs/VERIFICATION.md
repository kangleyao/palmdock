# 验证状态与已知缺口

本文件只陈述**验证过什么、没验证什么**，不含开发过程叙述。所有计数为当前仓库实测值。

## 怎么复现

```bash
npm install --ignore-scripts   # 安装依赖（见 docs/DEMO.md「从零安装与测试」说明，须带该参数）
npm run token                  # 生成随机 token 写入 config.json
npm run build                  # tsc 编译到 dist/
npm test                       # 编译 + 跑全部测试
```

可选的只读真实验证（需要本机装有 DeepSeek Harness，即 dsh 桌面产品）：

```bash
node scripts/verify-dsh-readonly.js
```

健康 → 列表 → 创建会话 → SSE 推送 → 消息 → 两个选项 → 回答 → succeeded + 结果 → 重复回答幂等不重放 → 断线 `sinceSeq` 续传 → 第二轮 turnIndex=1 → 失败流程 → 列表状态与预览 → 页面安全；服务以独立进程跨多个命令会话存活。

**对真实 DeepSeek Harness 的只读 API 验证（`scripts/verify-dsh-readonly.js`，5 项全过）**

**真机浏览器（一次完整流程，旧版界面）**

## 未验证 / 已知缺口

- **真机提醒的实际效果**：手机是否真的振动、后台标签页是否真的出声，需真机复验。
- **系统通知**：明文 HTTP 下不可用（需 HTTPS）；iOS Safari 无 Notification API；Android Chrome 通常可用但未实测。
- **跨网隧道**：`docs/CLOUDFLARE-TUNNEL.md` 仅为方案文档，未配置、未实测。
- **真实复杂形态**：真实 DSH 上的多题 / 多选 / 自由文本 / 审批与长对话表现未验证（协议层处理已模拟覆盖）。
- **性能**：高并发 / 大数据量未压测。
- **调度槽**：`awaiting_answer` 期间占用并发槽（默认 4），未做超时回收。
- **完全关闭浏览器仍收通知**：需要系统级推送服务（公网暴露），被安全边界禁止，属已知缺口。
- **Android 壳真机表现**：构建与签名已验证，装上后的实际提醒表现需真机确认。
